# Gameplay Loop

## Canonical loop

1. **Focus** — inspect a record, log, object, or conversation.
2. **Form a thread** — the player begins holding a question or hypothesis in mind.
3. **Interruption** — a system/NPC event demands attention.
4. **Preserve or switch** — use Quick Pin or switch without it.
5. **Secondary task** — complete a short, bounded activity.
6. **Return** — resume the original investigation.
7. **Recover** — reconstruct the previous thread using memory and/or Quick Pin.
8. **Cross-check** — compare old and new evidence.
9. **Deduce** — answer a focused question.
10. **Reflect** — notice what supported recovery.

## Loop 01: Coupler

- Start: Maintenance record states COUPLER REPLACED.
- Active thread: verify whether the replacement really happened.
- Interruption: short incident-system request.
- Optional action: Quick Pin the current thread.
- Secondary task: 20–40 second unrelated system action.
- Resume: return to Maintenance/Storage investigation.
- Evidence: replacement record + new coupler still in Storage + serial match.
- Deduction: the coupler was not replaced.

This loop is the implementation contract for the first build.
