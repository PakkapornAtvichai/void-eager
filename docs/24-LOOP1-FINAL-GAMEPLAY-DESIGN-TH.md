# VOID-EAGER — สรุปแผน Gameplay Loop 1 ฉบับล็อก (ภาษาไทย)

**วันที่:** 29 ตุลาคม 2026
**สถานะ:** ล็อกแนวทางออกแบบเพื่อเริ่มแก้โค้ดครั้งถัดไป — **ยังไม่ได้เปลี่ยน Gameplay ในโค้ดตามแผนนี้**
**สเปกเทคนิคฉบับละเอียด (English):** [24-LOOP1-FINAL-GAMEPLAY-DESIGN.md](24-LOOP1-FINAL-GAMEPLAY-DESIGN.md)
**ขอบเขต:** เฉพาะ Coupler Loop 1 เป้าหมายเกมสั้น 5–10 นาที ไม่ขยายเป็น Mystery 6 ห้อง ไม่เพิ่ม NPC ระบบ AI หรือภาพใหม่

> **ประสบการณ์ที่ต้องการ:** “ฉันกำลังคิดว่าจะตรวจอะไรต่อ แต่ถูกงานอื่นเข้ามาขัด พอกลับมาต้องนึกและเลือกเองว่าจะสืบเรื่องเดิมอย่างไร”

## 1. ทำไมต้องแก้แบบนี้

ผลทดลองเล่นก่อนหน้าแสดงว่าเกมกดปุ่มจนจบได้ แต่ไม่ค่อยได้ใช้ความคิด เพราะ:
- Work Order บอกชัดจนเกือบเฉลยข้อสงสัย
- C-17 ถูกตั้งเวลาให้มาหลังเปิดรายงาน 12 วินาที โดยไม่สนใจว่าผู้เล่นกำลังคิดอะไร
- Quick Pin บันทึกข้อความสำเร็จรูปที่อาจเป็นสิ่งที่ผู้เล่นยังไม่เห็น
- Storage Lead กดตามไปได้เฉพาะหลังจบ Coolant ซึ่งไม่สมเหตุสมผล
- หน้าหลักฐานใน Storage บอกคำสรุปแทนผู้เล่น
- Objective Guide ให้คำแนะนำละเอียดจน Quick Pin แทบไม่จำเป็น
- Reflection เป็นเพียงคำถามบนจอ ไม่มีที่ให้ตอบ

**ทางแก้:** ไม่เพิ่มระบบการสืบสวนใหญ่ขึ้น แต่ทำให้ผู้เล่นได้ “เลือกสิ่งที่กำลังตรวจ → ถูกขัด → เลือกวิธีจำ → กลับมาตรวจต่อ → เปรียบเทียบ → ตั้งข้อสันนิษฐาน”

## 2. เรื่องราวที่ใช้เฉพาะ Loop 1

- ยาน **Void-eager** เกิด **Guidance Stabilizer Cascade Failure**
- ผู้เล่นคือ **Incident Systems Officer** ไม่ใช่ Detective มีหน้าที่ตรวจข้อมูลข้ามระบบ/แผนก
- **Glint** ฝ่าย Maintenance ทำ Work Order **WO-4471** ระบุว่าเปลี่ยน Stabilizer Coupler แล้ว
- Serial ของชิ้นที่บันทึกว่าเปลี่ยนคือ **GSC-8842-A** โดยมีที่มาจาก **Storage B-04**
- ใน Storage มีอะไหล่ replacement ที่มี Serial เดียวกันและอยู่ในสภาพ **unused**
- เป้าหมายผู้เล่นคือ **ตรวจว่าคำกล่าวอ้างใน Work Order สอดคล้องกับหลักฐานจริงไหม** ไม่ใช่จับผู้ร้ายทั้งคดี

**ยังไม่ทำ Opening Conversation** กับ Maven หรือ NPC อื่น ใช้ระบบแจ้งงานสั้น ๆ สองบรรทัดพอ:
- “Void-eager reported a stabilizer cascade.”
- “Glint's record says the Coupler was replaced. Check that claim.”

**สิ่งที่ไม่เฉลยใน Loop 1:** คนที่สร้างความเสียหายทั้งหมด เหตุจูงใจเต็มรูปแบบ ที่ซ่อน Coupler เก่า และความจริงทั้ง 6 ห้อง

## 3. ผังประสบการณ์ของผู้เล่น

| ช่วง | ผู้เล่นทำอะไรจริง | การตัดสินใจที่มีความหมาย |
|---|---|---|
| 1. เริ่มคดี | เข้า Maintenance เลือกดู Workstation หรือสำรวจจุดอื่นก่อน | เลือกว่าจะเริ่มตรงไหน |
| 2. สืบ Work Order | เปิด WO-4471 อ่าน field สถานะ, Serial/Source, Installation Verification | เลือกว่าสิ่งใดควรตรวจต่อ |
| 3. C-17 เข้ามาขัด | เจอ Coolant Sensor Mismatch ขณะมีงานค้าง | Save Context / Handle / Later |
| 4. เปลี่ยนงาน | ตรวจข้อมูล Sensor แล้วเลือกการตอบสนอง | เลือกประเภทการรับมือ 1 ใน 3 แบบ |
| 5. กลับเข้าสู่คดี | เลือกกลับจุดที่ค้างหรือไป Hub | ใช้ Pin ที่ตัวเองเลือกไว้ หรือย้อนตรวจข้อมูลเอง |
| 6. Storage | เปิดกล่อง ตรวจสภาพอะไหล่ อ่าน Serial | เลือกตรวจสภาพหรือ Serial ก่อน |
| 7. Compare | เอาข้อมูล Work Order และชิ้นส่วนมาเทียบ | เลือกหลักฐานที่จะเชื่อมกัน |
| 8. Theory | เลือกความเห็นปัจจุบันพร้อมอ้างอิงหลักฐาน | เลือกได้ทั้ง “เปลี่ยนแล้ว” / “น่าจะไม่ได้เปลี่ยน”; กลับมาแก้ได้ |
| 9. Reflection | ตอบคำถามสั้น ๆ เกี่ยวกับการกลับมาทำงาน | บอกกลยุทธ์ที่ช่วยตัวเอง โดยไม่มีถูก/ผิด |

**ลำดับนี้เป็นเพียงทางเดินตัวอย่าง ไม่ใช่ล็อกห้อง:** ผู้เล่นไป Storage ก่อน Workstation ได้ หรือแวะ Power Log ก่อนได้ ถ้าข้อมูลยังไม่ครบ ให้เก็บข้อมูลที่พบไว้ แล้วเชื่อมความหมายภายหลัง

## 4. Workstation จะไม่ใช่แค่หน้าจออ่านรายงาน

**ใช้ข้อมูล 3 ส่วนเดิม ไม่สร้างเอกสารเพิ่ม:**
1. **SERVICE RECORD:** บันทึกงาน Maintenance 12 วันก่อนเกิดเหตุ
2. **RECORDED COMPLETION:** สถานะ COUPLER REPLACED; ผู้ทำงาน GLINT; Serial GSC-8842-A
3. **PARTS REFERENCE:** แหล่ง Storage B-04; INSTALL VERIFY: NOT ATTACHED

ผู้เล่นคลิกตรวจส่วนใดก่อนก็ได้ แล้วเกมถามเพียง **“What will you check next?”**

ให้เลือกจากสิ่งที่อ่านถึงแล้ว เช่น:
- **Check the completion record**
- **Trace the issued part**
- **Look for installation verification**

นี่คือ **Working Intention** หรือความตั้งใจที่กำลังจะทำ ไม่ใช่คำตอบถูกผิด และเปลี่ยนใจภายหลังได้

**กฎสำคัญ:** เมื่อเห็น Serial และ Source แล้ว ผู้เล่นกด Trace Part Source หรือไป Storage เองได้เลย ไม่ต้องรอจัดการ C-17

**ต้องตัดข้อความที่ชี้คำตอบ:** “INVESTIGATOR'S QUESTION // where is the installation proof?” เพราะตรงนั้นควรเป็นสิ่งที่ผู้เล่นตั้งคำถามเองจากข้อมูล

## 5. C-17 — ให้ขัดตอนมีสิ่งที่กำลังทำจริง

- C-17 คือ Coolant Telemetry Mismatch ที่ถูกส่งมาหา Incident Systems Officer เป็นงานรองที่ไม่ใช่เบาะแสคดี Coupler
- **ไม่ใช่** เปิดรายงาน 12 วินาทีแล้วเด้งทันที
- ให้เริ่มรอเกิดเหตุการณ์หลังผู้เล่นเลือก Working Intention ใน Workstation หรือเริ่มตรวจสภาพอะไหล่ที่ Storage
- ระยะเสนอเริ่มต้น **ประมาณ 6–8 วินาทีของช่วงกำลังทำงาน** แต่ไม่โชว์ Countdown; ถ้ามีหน้าต่างหลักฐานเปิดอยู่ ให้รอจนผู้เล่นปิดก่อน
- C-17 เกิด **หนึ่งครั้งต่อรอบเล่น** และไม่ถูกล้างหากผู้เล่นเปลี่ยนห้อง
- ตัวเลือกคือ **SAVE CONTEXT / HANDLE ALERT / LATER**
- ถ้ากด LATER ให้ย่อเป็นป้าย **C-17 PENDING** ซึ่งยังอยู่จนกว่าจะจัดการ
- **ไม่มีการยึดการควบคุมอัตโนมัติหลังหมดเวลา** ผู้เล่นเลือกจังหวะ Handle ได้

**งาน Coolant ใช้ข้อมูลเดิม:** Sensor A 72.1 C, Sensor B 54.0 C, Pressure Stable, Flow Nominal, Sensor B Intermittent

เลือกได้สามทาง: Log mismatch/monitor, Request maintenance check, Request emergency isolation ทั้งสามทางบันทึกการตัดสินใจและเดินเกมต่อได้ ไม่มีการให้คะแนนความสามารถด้าน Task Switching

เมื่อจบแล้วเลือก:
- **RETURN TO PREVIOUS TASK** — กลับตำแหน่ง/ข้อมูลที่กำลังตรวจ
- **INCIDENT HUB** — ไปเลือกเรื่องที่อยากทำต่อด้วยตัวเอง

ถ้า C-17 เกิดที่ Storage ก็กลับ Storage ได้จริง ไม่บังคับย้ายกลับ Maintenance


## 6. Quick Pin — บันทึกสิ่งที่ผู้เล่นตั้งใจจะทำต่อ

**ปัญหาเดิม:** ระบบ Pin ใส่ข้อความเกี่ยวกับ Serial และการไม่มี Install Verification ให้โดยอัตโนมัติ ทั้งที่บางคนอาจยังอ่านไม่ถึง ทำให้เหมือนระบบเฉลยแทนผู้เล่น

**วิธีใหม่:** ก่อนทำ C-17 หากผู้เล่นกด SAVE CONTEXT ให้ถาม **“What were you about to check?”** แล้วเลือกสิ่งที่ตัวเองตั้งใจจริง ๆ จากข้อมูลที่เคยเห็นแล้ว เช่น:
- “Trace the issued part”
- “Check the completion record”
- “Look for installation verification”

หากกำลังอยู่ Storage ตัวเลือกต้องเปลี่ยนตามงานจริง เช่น “Inspect condition” หรือ “Read serial plate” ห้ามยึด Workstation ตลอด

ข้อมูล Pin เก็บ:
- งาน/Thread ที่กำลังทำ
- ห้องและ Object/ส่วนรายงานที่กำลังเปิด
- **Working Intention ที่ผู้เล่นเลือก**
- ตำแหน่งเลื่อนรายงาน (ถ้ามี)

**ตอนกลับ:** คนที่ใช้ Pin กดดูข้อความที่ตัวเองเลือกไว้ได้ และไปยังจุดนั้นได้โดยตั้งใจ ส่วนคนไม่ใช้ Pin สามารถย้อนอ่านข้อมูลเดิมได้ตามปกติ ไม่ถูกลงโทษ

**ตำแหน่ง UI:** Quick Pin อยู่ตำแหน่งเดิมใน HUD แต่ต้องไม่ขยายตามไปบังหลักฐานใน Storage เหมือนบั๊กก่อนหน้า ภายนอก Hub เป็นเพียงสถานะ “Saved context” แบบย่อ การขยายและกด RESUME ทำจาก Hub หรือกดเปิดดูโน้ตอย่างตั้งใจเท่านั้น

**อย่าให้ Objective Guide แทน Pin:** หลังจบ C-17 แสดงเป้าหมายกว้าง ๆ ว่า “Continue the Coupler investigation” พอ ถ้าไม่ได้กด Hint ก็ไม่ควรบอกทันทีว่า “คุณกำลังจะไปเช็ก Serial ที่ Storage” เพราะนั่นคือความจำที่ผู้เล่นควรลองกู้คืนเอง

## 7. Storage — สังเกตก่อน ตีความทีหลัง

ใช้ภาพเดิมทั้งหมด: กล่องปิด/กล่องเปิด/Coupler/Serial Plate

ลำดับที่จำเป็นตามเหตุผลทางกายภาพคือ **เปิดกล่องก่อน** แต่หลังเปิดแล้ว:
- เลือก **Inspect condition** หรือ **Read serial** ก่อนก็ได้
- เมื่อกดดู ให้ขึ้นหน้าต่างรายละเอียดกลางจอ + **CLOSE** และกลับไปภาพเดิม
- ข้อความต้องเป็นข้อเท็จจริง เช่น “Condition: UNUSED”, “Serial: GSC-8842-A”, “Location: B-04”
- **ห้ามบอกว่า “จึงพิสูจน์แล้วว่าไม่ได้เปลี่ยน”** ภายในหน้าต่างหลักฐาน

ถ้าผู้เล่นเห็นทั้ง Work Order และ Serial Plate แล้ว จึงเปิด **COMPARE SOURCES**:
- ด้านหนึ่งเป็นสิ่งที่ WO-4471 *อ้างว่าเกิดขึ้น*
- อีกด้านเป็นสภาพและหมายเลขของอะไหล่ที่ผู้เล่น *เห็นจริงใน Storage*
- ผู้เล่นเลือกบันทึกการเปรียบเทียบเอง ระบบยังไม่ตัดสิน Theory ให้

ถ้าไป Storage ก่อนโดยยังไม่เคยเปิด Work Order จะเห็น Serial ของวัตถุ แต่ไม่มีหน้าต่างเทียบที่ดึงข้อมูล WO-4471 มาเผยก่อนเวลา

**ข้อสมมติของเกมที่ต้องล็อก:** GSC-8842-A เป็น Serial เฉพาะชิ้น ไม่ใช่ชื่อรุ่น/เลข Batch จึงมีน้ำหนักเมื่อตรวจพบชิ้นหมายเลขเดียวกันยัง unused อยู่ Storage ไม่ต้องเพิ่มเอกสารอะไหล่ชุดใหม่มาแก้เรื่องนี้

## 8. Case Review — สรุปเอง ไม่ใช่ข้อสอบ

- เข้าดู Case Review ได้เมื่อพบหลักฐานคดีอย่างน้อยหนึ่งแหล่ง ไม่ต้องรอ C-17 หรือ Serial ครบ
- รายชื่อ Evidence ที่ให้เลือกต้องแสดง **เฉพาะสิ่งที่ผู้เล่นตรวจแล้ว** ไม่ใช่ทุกหลักฐานของเกม
- เลือกข้อสันนิษฐานได้ทั้ง “การเปลี่ยนอะไหล่เกิดขึ้นจริง” และ “การเปลี่ยนที่บันทึกไว้น่าจะไม่เกิดขึ้น”
- ต้องเลือกอ้างอิงหลักฐานที่เห็นแล้วอย่างน้อยหนึ่งชิ้นเพื่อ Save
- บันทึกผิดก็ไม่ขึ้น Correct/Incorrect; กลับมาหาหลักฐานเพิ่มและแก้ Theory ได้
- หากยังไม่พร้อม มีปุ่ม **KEEP INVESTIGATING** กลับไปเล่นต่อ
- **End Session** ใช้ได้เมื่อมี Theory และจัดการ C-17 แล้วเท่านั้น ถ้ายังเหลือ Alert ให้แจ้งตรง ๆ ว่ายังมี C-17 Pending ไม่ใช่ล็อกไว้เงียบ ๆ

Power Log ยังอยู่เป็นทางเลือก: แสดง 21:11 Spike ก่อน และให้ผู้เล่นกดตรวจ 21:12 Protection เอง ห้ามโชว์ “ANOMALY CONTAINED” ตั้งแต่ก่อนตรวจ และห้ามทำให้มันเป็นหลักฐานบังคับของ Coupler Loop

## 9. Reflection — ตอบได้จริง แต่ไม่ตัดสินผู้เล่น

ถามสั้น ๆ 3 ข้อ พร้อมข้ามได้:
1. “How easy was it to return to your task?” — Easy / Some effort / Difficult / Prefer not to answer
2. “What helped you return?” — Quick Pin / Re-reading / Seeing the object / Remembering / Other / Prefer not to answer (เลือกได้มากกว่า 1)
3. “Did the interruption change your thinking?” — Yes / No / Unsure / Prefer not to answer

อาจมีช่องเขียนสั้น ๆ เพิ่มได้ถ้าไม่กินเวลา ผู้เล่นกด Finish หรือ Restart ได้เอง

ไม่มีคะแนน “ASD ดี/ไม่ดี”, ไม่มีผลวินิจฉัย และไม่มีการบอกว่า Quick Pin เป็นเทคนิคที่ถูกต้องเพียงวิธีเดียว เป้าหมายคือให้ผู้เล่นสังเกตประสบการณ์ของตัวเอง

## 10. กรณีเล่นนอกลำดับที่โค้ดต้องรองรับ

| สถานการณ์ | พฤติกรรมที่ต้องเกิด |
|---|---|
| เปิด Work Order แล้วไป Storage ก่อน C-17 | ไปได้โดยไม่ติดล็อก |
| เข้า Storage ก่อนอ่าน Work Order | เก็บข้อเท็จจริงได้ แต่ไม่ดึงข้อเท็จจริงของ WO-4471 มาบอกล่วงหน้า |
| เลือกไม่ Pin | เล่นต่อได้และย้อนดูข้อมูลเดิมได้ |
| Pin ตอนอยู่ Storage | Note ชี้กลับไปงานที่ Storage ไม่ใช่รายงาน Maintenance แบบตายตัว |
| C-17 มาแล้วกด Later และเปลี่ยนห้อง | C-17 ยังเป็น Pending และกลับมาเปิดได้ |
| C-17 มาระหว่างหน้าต่างหลักฐานเปิด | รอให้ผู้เล่นปิดหน้าต่างก่อนแจ้ง |
| เลือกคำตอบ Coolant แต่ละแบบ | เก็บ Response ต่างกัน แต่ไม่แยกเป็นคดีใหม่ |
| เปิด Power Log ก่อน | เป็นทางเลือก ไม่ทำให้คดีหลักติดล็อก |
| เลือก Theory ที่ยังไม่ตรงหลักฐาน | Save ได้ กลับมาแก้ได้ ไม่เฉลยถูกผิดทันที |
| เปิด Quick Pin ที่ Hub แล้วไป Storage | หน้าต่าง Pin ยุบ ไม่มี Resume Report บัง Serial |
| กดดู Evidence ซ้ำ | ไม่เพิ่มจำนวนหลักฐานซ้ำ |
| Restart | รีเซ็ต Pin, C-17, Findings, Theory, Reflection ของรอบก่อน |

## 11. ลงมือแก้โค้ดตามลำดับ (ยังไม่ได้ทำในรอบจัดทำเอกสาร)

**P0-A — Workstation และ Navigation**
แก้ให้รายงานเลือกตรวจ Field และเลือก Working Intention ได้; เปิดเส้นทาง Storage/Hub ได้โดยไม่ผูกกับ Coolant; ตัดคำใบ้ที่เฉลยล่วงหน้า

**P0-B — C-17, Quick Pin, Recovery**
เปลี่ยนเงื่อนไขการขัดจังหวะ, เก็บ Pending ทุกห้อง, Pin ความตั้งใจของผู้เล่น, Return to Task หรือ Hub ตามที่เลือก, ทดสอบแบบมี Pin/ไม่มี Pin

**P0-C — Storage Comparison และ Theory**
ใช้ภาพเดิมแต่แยกการตรวจสภาพ/Serial, ให้เลือกเทียบหลักฐาน, สรุปและแก้ Theory โดยอ้างข้อมูลที่เคยเห็นจริง

**P0-D — Reflection และทดสอบ**
เพิ่มการตอบคำถามสั้น ๆ ทดสอบเส้นทางนอกลำดับทั้งหมด ตรวจ UI ไม่ล้น/ไม่ทับบนจอ 1280×720, 1464×815, 1920×1080 และให้คนที่ไม่เคยเห็นเกมอย่างน้อย 3 คนลองเล่นโดยไม่บอกทาง

### เงื่อนไขที่ถือว่า Prototype รอบนี้สำเร็จ

ผู้เล่นใหม่ควรสามารถ:
- บอกได้ว่ากำลังตรวจข้อกล่าวอ้างอะไร
- เลือกเองได้ว่าควรตรวจข้อมูลส่วนไหน
- รู้สึกว่ามีงานค้างอยู่เมื่อ C-17 เข้ามาขัด
- กลับมาทำงานได้ทั้งโดยใช้ Pin และไม่ใช้ Pin
- เทียบ Work Order กับอะไหล่ที่ Storage และอธิบายข้อสงสัยด้วยตัวเอง
- บันทึก Theory และตอบ Reflection ได้ โดยไม่ต้องให้ผู้พัฒนาบอกว่าต้องกดอะไรทีละขั้น

**สิ่งที่ห้ามเพิ่มระหว่างทำ P0:** NPC ใหม่ ห้องใหม่ คดีใหม่ AI บทสนทนาเปิดเกมยาว ๆ ปริศนาหลอกให้เสียเวลา หรือลำดับที่บังคับว่าต้องทำ C-17 ก่อนถึง Storage
